# Правила работы с проектом DeepSeek Agent

## Назначение

Это локальный Windows-веб-чат на Flask с DeepSeek, JSON-хранилищем диалогов,
пресетами, стратегиями управления контекстом, ветвлением и локальным Whisper.

Перед нетривиальным изменением прочитай `docs/PROJECT_MAP.md`, затем открывай
только файлы, относящиеся к задаче. Не перечитывай весь проект без причины.
Архитектурные решения и ограничения записаны в `docs/DECISIONS.md`.

## Язык и формат работы

- Общайся с пользователем и обновляй проектную документацию на русском языке.
- Сначала отвечай на буквальную задачу, затем указывай только существенные риски.
- Если пользователь просит сначала обсудить решение, не редактируй файлы до
  явного согласования.
- Не добавляй функции вне поставленной задачи.
- Сохраняй существующие пользовательские изменения в рабочем дереве.

## Обязательные границы совместимости

- Не удаляй и не переименовывай существующие режимы `full`, `summary`,
  `sliding`, `facts` без отдельного согласования.
- Ветвление не является пятым режимом: дерево сообщений работает поверх всех
  четырёх стратегий контекста.
- Сохраняй обратную совместимость JSON-диалогов schema version 3. Старые
  линейные сообщения должны безопасно получать `parent_id` при чтении.
- Не теряй исходные сообщения, summary-ревизии, facts, fact-ревизии и ветки.
- Ручные facts с `locked=true` должны сохраняться при автоматическом обновлении.
- Не включай неуспешные запросы в будущий контекст.
- Снимок настроек запроса и фактические токены ответа должны оставаться
  привязанными к соответствующему сообщению.
- Основные токены диалога, токены summary и токены извлечения facts учитываются
  раздельно.
- Пользовательские диалоги и пресеты находятся в `data/`; не изменяй реальные
  данные для тестирования.

## Безопасность и внешние сервисы

- API-ключ хранится только в `.env`. Не печатай, не логируй и не коммить его.
- Не выполняй реальный запрос DeepSeek без явной необходимости и предупреждения
  о том, что он использует сеть и может расходовать средства.
- Локальные тесты используют подменённый провайдер и не подтверждают работу
  актуального внешнего DeepSeek API.
- Голосовой ввод должен оставаться локальным. Не отправляй аудио во внешние
  сервисы.
- Не добавляй в Git модели, FFmpeg, сборки whisper.cpp, логи, `.env` или
  пользовательские JSON-диалоги.

## Где вносить изменения

- Провайдер, настройки и метаданные LLM: `agent.py`.
- Стратегии контекста, facts и дерево веток: `context_manager.py`.
- JSON-схема, импорт и экспорт: `storage.py`.
- HTTP API и оркестрация запроса: `app.py`.
- Пресеты: `presets.py`.
- Локальный Whisper: `voice.py` и `setup_voice.ps1`.
- Браузерная логика: `static/app.js`.
- Разметка и стили: `templates/index.html`, `static/style.css`.
- Поведение и регрессии: `test_app.py`.

Подробные зависимости, поток запроса и карта API находятся в
`docs/PROJECT_MAP.md`.

## Проверка изменений

Используй Python из проектного окружения:

```powershell
.\.venv\Scripts\python.exe -m unittest -v
.\.venv\Scripts\python.exe -m py_compile agent.py context_manager.py storage.py app.py test_app.py
node --check static\app.js
git diff --check
```

- Для узкой правки сначала можно запустить соответствующий тест, но перед
  завершением изменения выполни полный подходящий набор проверок.
- При изменении интерфейса дополнительно проверь изменённый сценарий в браузере
  и отсутствие ошибок в консоли. Не совершай для этого реальный LLM-вызов.
- Не утверждай, что живой DeepSeek API проверен, если использовался fake/mock.
- Перед отчётом перечисли выполненные проверки и честно укажи непроверенное.
