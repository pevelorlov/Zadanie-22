# День 21. Локальная индексация документов

## Назначение

Раздел **«Управление RAG»** строит локальный документальный индекс и сравнивает
две стратегии chunking. В День 21 найденные чанки не передаются DeepSeek.

## Корпус

Положите документы в `rag_documents/`. Поддерживаются:

- `.pdf` — только готовый текстовый слой, без OCR;
- `.docx` — заголовки, абзацы, списки и текст таблиц; изображения не распознаются;
- `.txt`;
- `.md`;
- `.html` и `.htm` — без исполнения JavaScript.

Подкаталоги обходятся рекурсивно. Остальные расширения игнорируются. Папка и
создаваемый `data/rag_index.sqlite3` не попадают в Git.

## Стратегии

### Fixed

Весь текст документа режется на диапазоны заданного числа токенов. Следующий
диапазон повторяет `overlap` последних токенов предыдущего.

### Structural

Markdown делится по иерархии заголовков, DOCX — по стилям заголовков и таблицам,
HTML — по `title`/`h1`–`h6`, TXT — по абзацам, PDF — по страницам и текстовым блокам. Слишком большой структурный блок
дополнительно делится по максимальному размеру с overlap.

Начальные настройки обеих стратегий: 350 токенов и overlap 50. Допустимый размер
чанка — 32–500 токенов; overlap обязан быть меньше размера.

## Эмбеддинги и хранение

Локальная CPU-модель `intfloat/multilingual-e5-small` создаёт нормализованные
float32-векторы размерности 384. Документы получают префикс `passage:`, поисковый
запрос — `query:`. SQLite содержит таблицы `index_runs`, `documents`, `chunks` и
`embeddings`; векторы хранятся как BLOB.

Для каждого чанка сохраняются `chunk_id`, стратегия, `document_id`, `source`,
`title`, `section`, страница PDF, порядок, число токенов, полный текст и SHA-256.

## Визуальная проверка

1. Откройте **«Управление RAG»**.
2. Проверьте список файлов и параметры.
3. Нажмите **«Построить оба индекса»** и дождитесь статуса «Индекс готов».
4. Сравните количество, средний, минимальный и максимальный размер чанков.
5. Выберите чанки с обеих сторон и проверьте текст и метаданные.
6. Введите запрос, установите `top-K` и сравните выдачу Fixed/Structural.

Индексация и поиск локальны. DeepSeek и его API-ключ не используются.
